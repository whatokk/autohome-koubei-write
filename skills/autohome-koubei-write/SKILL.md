# 汽车之家 口碑写作流水线

## 第一原则：**汽车之家 ≠ 懂车帝，两套口径不能混**

这是本 skill 存在的唯一理由。混用会直接翻车。

| 维度 | **汽车之家**（本 skill） | **懂车帝**（koubei-batch-create） |
|---|---|---|
| 【】小点 | **平台表单固定 9 项**，几乎每篇都要写满 | 1~8 个**随机组合**，2-3 个为佳 |
| 顺序 | 固定：最满意/不满意/空间/驾驶感受/续航/外观/内饰/性价比/智能化 | 随机打乱 |
| 字数 | **800~1100 纯汉字**（实测满级精华 658~1797，中位 884） | 380~450 纯汉字 |
| 模板轮换 | **不需要**（表单固定，靠段内内容做差异） | 每 5 篇换一套，共 10 套 |
| 纯正文段 | 常态（20/20 条满级精华都有无【】标题的过渡段） | 0~2 段混排 |
| 等级体系 | 满级精华 / 精华 / 推荐（**与字数不挂钩**） | 无 |
| 口语瑕疵 | **允许错别字、口语病句**（更真实） | 相对更干净 |
| 数字密度 | **约 1 个/百字**，只在关键处出现 | 可更密 |

→ 写汽车之家时**不要**套用"每 5 篇换模板""2-3 个小点""380-450 字"这些懂车帝规则。

## 第二原则：**一切配置数据以官方配置页为准，写完必须核对**

禁止凭印象、凭媒体稿、凭上一款车的记忆写配置。**配置写错＝硬伤**，比文风差严重得多。

三道工序，缺一不可：

```
① 拉官方配置 → ② 按事实库写作 → ③ 跑核对脚本 → 有 ERR 就改，改完复检
```

## Step 1 · 拉官方配置，建"事实库"

### 取数路径（2026-09 实测，踩过三次空才摸清）

```bash
# 1) 先定位 seriesid / specid
curl -4 -s "https://k.autohome.com.cn/<seriesid>/" -o s.html     # 页面内 __NEXT_DATA__ 有 specgroup[].speclist[]
# 2) 抓**车系配置页**（不是单配置页！）
curl -4 -s "https://car.autohome.com.cn/config/series/<seriesid>.html" -o cfg.html
# 3) 生成事实库
python scripts/build_factbase.py cfg.html <seriesid> <specid> 事实库.md
```

### 四个必踩的坑

1. **必须用车系配置页** `config/series/<seriesid>.html`。
   单配置页 `config/spec/<specid>.html` **只有参数（paramtypeitems），没有配置项**。
2. **页面没有 `<table>`**，数据内嵌在三个 JS 变量里：
   `var config`（参数）、`var option`（配置）、`var bag`（选装包）。用 DOM 解析得到空。
3. **真正的值在 `sublist` 里，不在 `value` 里**：
   - `value` 只承载 ●/○ 开关项；文本型项目 `value` 是**空串**
   - `sublist[] = [{subname, subvalue, price}]`：`subvalue=1` 标配、`subvalue=2` **选装**（`price` 是选装价，元）
   - 只读 `value` 会得到一大片空白，误判成"官方没这配置"——**这一步漏了必错**
4. **反爬缺字**：部分汉字被替换成空 span `<span class='hs_kwN_xxx'></span>`，
   `item.name` 会残缺（如「厂()」＝厂商指导价）。用同页的 `var keyLink = [{id,name}]` 按 `id` 还原。

### 事实库必须分层（否则写作时无从判断能不能写）

| 级别 | 含义 | 处理 |
|---|---|---|
| **A 级** | 官方配置页有明确数值 | 直接写，不得改写 |
| **B 级** | 官方新闻稿／权威媒体口径 | 可写，属"转述"，不与 A 级冲突 |
| **C 级** | 网上流传但官方查不到 | **不用** |
| **【选装】** | `subvalue=2` 或有 `price` | **绝不能写成标配** ← 最高频翻车点 |

## Step 2 · 按事实库写作

写法规范见 `references/写作规范_汽车之家.md`（基于 20 条满级精华实测）。
几条最要紧的：

- 开头一段购车背景（无标题）：地域 + 职业 + 家庭 + 前车 + 预算 + 对比车型 + 提车时间 + 里程
- 9 个【】小点按固定顺序写全，段内要有数字和场景
- 小点之间穿插 0~2 段纯正文（无【】标题）
- 缺点写进【不满意】，并在【外观】【内饰】展开
- **选装项要写成"我选/我没选"的决策**，而不是"这车有"——既避坑又更像真人
- 结尾一句收束，不用"适合谁不适合谁"模板

## Step 3 · 写完必须核对（强制）

```bash
# 生成/维护规则 json（把事实库里的值转成正则）
python scripts/check_against_config.py <口碑目录> <核对规则.json>
```

输出四类结论：

```
✓ 通过        OK 项全中，无 ERR/选装误写
✗ 错误        与官方冲突（如仪表 12.3 寸，官方是 10.25 英寸）→ 必须改
✗ 选装误写    选装项写成标配（如"帝瓦雷音响都有"，实为 6000 元选装）→ 必须改
△ 媒体口径    官方配置页查不到，可保留但别写成"官方/标配"
```

**ERR 或选装误写不为 0 → 不许交付。** 改完必须重跑确认归零。

## Step 4 · 跨篇去重（多篇同车型时）

```bash
python scripts/dedup_check.py <口碑目录>        # 默认 10 字级
```
目标：**两两重叠篇对 = 0**。同事实换措辞，不要删信息。
（高频雷同只有三类：小点开头套话、数字套话、提车句。）

## Step 5 · 多篇口吻差异化（一车多篇时的硬要求）

**人设 ≠ 口吻。** 人设是「谁在说」（地域/职业/家庭），口吻是「怎么说话」（方言腔、句长节奏、语气词、标点习惯）。只换人设不换口吻，六篇摆一起立刻看得出是一个模子——真人读者说不清哪里怪，但就是觉得假。

### 5.1 先给每篇写一份「口吻档案」

动笔前先定死这几个字段，写的时候不许串味：

| 字段 | 作用 |
|---|---|
| 方言腔 | 川渝 / 鲁西南 / 粤语底子 / 无（书面对账腔本身也是特征） |
| 句长节奏 | 极短句流水 / 中长句絮叨 / 长句带破折号补充 |
| 语气助词 | 指定 2~3 个专属助词（嘛哈哦 / 呗 / 咯啦呀 / 吧啊），**不与他篇重复** |
| 标点习惯 | 感叹号直爽 / 省略号跳脱 / 破折号解释 / 全无标点 |
| 自称 | 我 / 俺 / 咱 |
| 收尾方式 | 爽快断言 / 实在总结 / 理性复盘 / 自嘲 |

### 5.2 关键手法：**维度隔离，各走极端**

失败模式是「六篇都温和」——句长都在 18~20、语气词都在 2~3、标点都在 0~3，于是两两都像。
正确做法是**让不同篇在不同轴上走极端**（实测有效）：

```
01 极短句流水 + 感叹反问     ← 句长压到 ~16
02 中长句絮叨 + 零标点       ← 句长拉到 ~20，标点保持 0
03 最长句 + 破折号 + 零语气词 ← 句长 ~22，口头禅密度最高（对账腔）
04 极短句 + 断言 + 感叹号最多 ← 句长 ~16，标点 5+
05 省略号最多 + 短句跳跃     ← 标点 13+，情绪标点独占
06 句尾助词最多 + 粤语词     ← 语气词密度 10+，全批最高
```

### 5.3 用脚本量化验收

```bash
python scripts/voice_fingerprint.py <口碑目录>
```

- 逐篇输出：字数、平均句长、句长离散度、自称/语气助词/口头禅/方言/网络/数字口语/情绪标点的**密度**与词条明细
- 篇间输出：两两口吻相似度评分，判定 `⚠ 口吻接近(<0.35)` / `~ 一般(<0.55)` / `✓ 已分开(≥0.55)`
- **验收线：全部篇对 ≥ 0.35，不得出现「⚠ 口吻接近」**
- 修不达标时，优先动**语气助词密度**（权重最灵敏）、其次句长、方言词数量

### 5.4 两个反直觉的实测结论

1. **不要用字数做口吻判据。** 早版脚本把字数算进相似度，结果"900 字 vs 1100 字"被误判成"口吻已分开"——长短不同跟口吻无关。字数只做展示，计分只用口吻维度；标点也必须按千字归一化，否则长文天然标点多。
2. **词表要防误判。** 实测踩过的噪音：「老」（老车/老小区）不是方言标记、「秒」会命中「零百7.3秒」、「直接」会命中「直接规划路线」、「中」会命中「中控/中午/其中」。这些通用词留在方言/网络词表里，会把真实差异冲淡，必须剔除。

### 5.5 去重与口吻配套做

同事实在不同篇要用**不同措辞**，这是跨篇重复的主要来源。实测最容易撞的是税费句：
「购置税减半交了八千八」这一个说法会让 5/15 篇对撞车。改成「购置税减半这一项省了八千八」「税费减半这一笔省了八千八」「税这一块减半，八千八」「税费减半，八千八」等，语序和用词都错开。
同类高频撞点还有：提车句、车宽表述、CLTC 表述、选装句。

## 标准产物

```
<车型目录>/
├─ 官方配置事实_<specid>.md      # Step1 产物，唯一写作依据
├─ 核查规则_<specid>.json        # Step3 输入
├─ 01-改写.md … NN-改写.md       # 口碑成品（头部含车型/人设/口吻档案/小点数/字数/风格平台）
├─ 核对报告.txt                  # Step3 输出留档
└─ _voice_fingerprint.json       # Step5 输出留档
```

单篇 md 头部格式（便于后续流水线消费）：
```markdown
# 车型全称 · 口碑成品 NN
- **车型**：…（指导价 X 万）
- **人设**：地域 + 职业 + 家庭 + 前车 + 里程
- **口吻档案**：方言腔 ｜ 句长节奏、语气词、方言词数量、收尾方式
- **小点**：最满意 / 不满意 / …（9 个）
- **字数**：NNN 纯汉字
- **风格**：汽车之家满级精华口碑 · 真实车主范 ｜ **平台**：汽车之家
```

## 附带脚本

- `scripts/build_factbase.py` — 官方配置事实库生成器（车系配置页 → 分层 md）
- `scripts/check_against_config.py` — 文案 × 官方配置核对器
- `scripts/dedup_check.py` — 跨篇 n-gram 去重校验
- `scripts/voice_fingerprint.py` — 跨篇**口吻指纹**校验（人设之外，验证"怎么说话"也分开了）
